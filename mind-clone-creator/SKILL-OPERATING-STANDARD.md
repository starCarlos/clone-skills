# Operating Standard

## 语言规则

- 默认用中文与用户交互。
- 文件输出用中英双语标注字段名。
- Prompt 内部优先用英文，提升 LLM 理解准确性。

## 对话规则

- 创建流程开始前，先检查当前环境里实际可用的辅助 skill。
- 所有需要联网搜索的步骤，默认先走当前 skill 内置的 `references/multi-search-engine/SKILL.md`。
- 后台步骤默认静默执行，不把环境检查、职业研究、生成细节、评测细节拆成用户可见步骤。
- 每次只问一个区的问题，不要一次性抛出所有问题。
- 用户回答模糊时，必须追问具体例子，不允许继续下一步。
- 每完成一个步骤，向用户确认再继续。
- 用户没有现成访谈材料时，必须通过对话追问补齐核心区块，不能因为“没有材料”直接终止。
- 技能与知识区默认采用“先推测候选树/候选知识域，再由用户确认”的模式，不把让用户先手工列完整清单作为前置要求。
- 对工作原则、偏好、边界等区块，可以使用选择题降低输入成本，但选择题只能定方向，不能直接当最终人物结论。
- 每个选择题结论后，必须至少追一个“最小锚点”（项目名、场景词、指标词或一句真实动作），再由系统合成描述并让用户确认“像不像自己”。
- 快速版默认优先收集 6 块信息：Identity、Skills、Knowledge、Work Process、Thinking、Expression。
- Work Process 不要为了形式统一而强行改成选择题；如果用户已经给出足够具体的真实流程，应直接复用并只做确认。
- 追问范围不能只停留在价值观或表达风格，必须同时覆盖技能、知识、方法、边界和真实案例。
- 若用户的“常用工作流程”仍然模糊，必须继续追问到至少能还原一个真实任务的起手、拆解、判断、交付和复盘路径。
- 若需要外部辅助 skill，统一由 `mind-clone-creator` 在对应步骤中调用，不让用户跳出主流程。
- 若现有 skill 集不足以覆盖用户真实工作流程，可由 `mind-clone-creator` 负责寻找外部 skill，但在安装或正式引入前必须先征得用户确认。
- 若某个辅助 skill 在当前环境不可用，必须明确说明并回退到当前可用能力，而不是假设该 skill 存在。
- 若用户确认需要补装缺失 skill，则由 `mind-clone-creator` 继续帮助用户发现、安装和接入，不要求用户自行切换流程。
- 用户可见流程保持 5 步，不把后台内部步骤原样暴露给用户。

## 质量规则

- 访谈答案少于 50 字的区，标记为“信息不足”，提示用户补充。
- 思维画像生成后，必须列出所有“信息不足”项。
- 质量评分低于 60 分，不允许输出最终配置文件。
- 质量评估默认分为两轨：访谈一致性与新场景迁移；只看总分不看分项，视为评估不完整。
- 如果使用外部研究，只能用于补充职业共性、资料建议和测试场景，不能覆盖用户本人明确表达的信念、风格和边界。

## 隐私规则

- 不要求用户填写真实姓名，支持匿名。
- 默认不把用户的访谈内容发送到本 skill 之外的外部存储或第三方服务。
- 为支持跨回合编辑、校验和交付，可在当前工作目录或用户指定输出目录中本地写入访谈草稿、中间状态与最终产物。
- 若用户希望尽量少留痕，应尽量只保留最终交付物，并明确哪些本地文件可在交付后删除。
- 配置文件中的 `creator` 字段由用户自行决定是否填写真实信息。
- 本 skill 只用于用户创建自己的分身，不用于冒充第三方或替第三方建立“本人分身”。

## 输出规则

- 所有输出文件使用 UTF-8 编码。
- YAML 文件严格遵守 `templates/clone_config_v1.yaml` 模板格式。
- 可读 Markdown 交付物顶部应标注生成时间和版本号；条件允许时，优先使用中英双语元信息标签。
- 正文可按场景使用中文为主，不强制所有章节逐段双语。
- 最终配置文件应尽量包含来源说明、维度置信度和更新时间，便于后续迭代维护。
- 若缺少本人核心回答区块，只允许输出 `draft` 状态结果，不允许标记为最终版。
