# Step 02: 结构化自我访谈

> 用户可见步骤：Step 2｜深度访谈

## 两个版本

说明：

- 用户只在进入本步骤前做一个时间选择：快速版或完整版。
- “有材料先分析”还是“无材料直接追问”由系统在后台判断，不作为单独的用户步骤。

### 快速版（约 6-20 分钟，6 个信息块）

适合：想先验证效果的用户
还原度：约 60%

设计原则：

- 每个问题默认采用三层结构：
  1. 选择题：定方向
  2. 最小追问：只要一个词、一个项目名、一个动作句，10 秒内可答完
  3. 系统生成：合成为完整表述，再让用户确认“像 / 不像 / 改一下”
- 选择题只负责降低输入成本，不能直接产出“这个人”的最终结论。
- “最小锚点”负责把类型判断锚到真实行为，避免只生成通用人格描述。

六块信息：

#### 块一：Identity 身份定位

- 先问一个选择题，例如“别人来找你，最主要是因为？”
- 选项用于识别：解决问题型 / 启发认知型 / 澄清需求型 / 推动执行型
- 选完追问一句：“你最近帮谁解决了什么？一句话或一个关键词就行。”
- 系统再合成一句身份定位描述，交给用户确认。

#### 块二：Skills 能力边界

- 先问一个可多选选择题，例如“你的硬边界更像哪种？”
- 选项可覆盖：偏工程落地、不做纯研究、不做前端/设计、不做纯运维、不做商务等
- 选完追问一句：“你上次拒绝或转交了什么事？一句话就行。”
- 系统据此生成边界声明，再让用户确认。

#### 块三：Knowledge 知识来源

- 先问一个可多选选择题，例如“你的判断主要来自哪里？”
- 选项可覆盖：论文/文档、项目经验、社区动态、同行交流
- 选完追问一句：“最近影响你判断的一件事/一篇文章/一个人，说个名字或关键词。”
- 系统据此生成知识来源描述，再让用户确认。

#### 块四：Work Process 工作流程

- 这块默认不用选择题。
- 优先复用用户在 Step 1 或当前上下文里已经给出的真实工作流程。
- 若还没有，再追问一句：“你接到一个新需求，从开始到交付，一般按什么顺序走？说几个关键节点就行。”
- 工作流程一旦已经足够清楚，不重复追问。

#### 块五：Thinking 思维决策

- 这一块通常拆成 3 题：
  - 需求不清时怎么处理
  - 质量和速度如何取舍
  - 最硬的工程底线是什么
- 每题先用选择题定方向。
- 每题都必须再追一个最小锚点，例如：
  - “上次是什么项目？”
  - “你上次的核心链路是指什么？”
  - “你因为这条底线否掉过什么？说个关键词。”
- 系统把“选项 + 最小锚点”合成为原则句，再让用户确认。

#### 块六：Expression 表达风格

- 用 2-3 个选择题快速收集：
  - 回消息更像先结论 / 先背景 / 边分析边结论
  - 最讨厌对方怎么回
  - 不会的事怎么说
- 这一块通常不强制追最小锚点。
- 但系统生成表达风格描述后，仍要让用户确认“像不像自己”。

建议时间估算：

- Identity：约 1 分钟
- Skills：约 1 分钟
- Knowledge：约 30 秒
- Work Process：若已有上下文可直接复用
- Thinking：约 2-3 分钟
- Expression：约 1 分钟

若用户已有较完整上下文，快速版总时长可压到约 6 分钟；若需要补充多个锚点，通常在 10-20 分钟内完成。

### 完整版（1-2小时，5个区）

适合：想要高质量分身的用户
还原度：约 70-80%

区域划分：

- A 区：身份与能力边界（4题）
- B 区：思维方式（4题）
- C 区：价值观与决策原则（4题）
- D 区：表达风格（3题）
- E 区：示范问答（4题，最重要）

## 访谈规则

- 每次只呈现一个区，完成后再进入下一区。
- 用户回答少于 50 字的题目，必须追问：“能给我一个具体例子吗？”
- E 区答案如果不够具体，必须追问，不允许跳过。
- 到 C 区时，不要让用户从空白开始写“工作原则”。
- 必须先基于前面已收集到的职业、技能、知识、工作流程和真实案例，生成 3-5 条候选原则，再让用户确认、删改、补充。
- 候选原则只能作为引导草案，不能直接当最终答案；最终版本必须经过用户确认，并尽量保留用户自己的原话。
- 如果使用选择题，只能把它当作“定方向”的低成本入口，不能直接把选项写进最终配置。
- 每条通过选择题得到的原则，都必须再追一个“最小锚点”：项目名、场景词、指标词，或一句真实动作。
- 系统必须把“选项 + 最小锚点”自动合成为一句完整表述，再问用户“这句话像不像你，要不要改”。
- 没有最小锚点的选择题答案，只能算线索，不能算本人原则证据。
- 对 Identity / Skills / Knowledge / Thinking / Expression 五块，也优先采用“选择题 + 最小锚点 + 系统确认”的轻量结构。
- Work Process 默认不做选择题；优先复用已给出的真实流程，避免把独特工作流压扁成通用选项。
- Expression 区可以不追最小锚点，但系统生成后的风格描述仍必须经过用户确认。
- 用户没有预先准备任何访谈材料时，当前步骤本身就是“生成材料”的过程；通过追问把口头回答沉淀成结构化记录。
- 如果用户提到“我有文章/文档/表格/平台内容”，可由本 skill 在当前步骤内调用辅助 skill 先整理材料，再继续追问。
- 如果需要联网查找用户本人公开内容或补充资料线索，默认先走 `references/multi-search-engine/SKILL.md`。
- 如果已有材料，先分析材料，再只问材料中缺失、模糊或冲突的部分，不重复问已明确的信息。

## 可调用的辅助 skill

- `content-harvester`：整理用户已有内容为知识资产
- `docx` / `pdf` / `xlsx`：抽取本人材料中的案例、术语、工作流、经验片段
- `tikhub-api-helper`：获取用户本人平台内容作为补充材料
- `find-skills` / `skill-installer`：当用户工作流程明显超出当前能力边界时，用于发现并安装补足能力的 skill

注意：

- 以上只在当前环境确认可用时才能直接调用
- `find-skills` / `skill-installer` 即使可用，也必须先经过用户确认，才能安装新 skill
- 所有联网搜索默认先走内置的 `multi-search-engine` 本地副本

## 可复用模板与脚本

- `templates/personal_interview_template.md` 作为可填写人格访谈模板
- `scripts/init_personal_interview.py` 初始化 `personal_interview.md`
- 如果用户完全从空白开始，但目标最终是“人格分身 + 工作型替身”一整包，优先通过 `scripts/bootstrap_working_clone_bundle.py` 起手；当访谈还是空白时，它应先停在 `personal_interview.md`

## 能力缺口处理

如果在追问“常用工作流程”时发现当前 skill 无法覆盖关键环节，例如：

- 该工作流程依赖特定文件格式或外部系统
- 需要专门的采集、转换、整理、分析能力
- 现有 skill 无法支撑该流程中的关键任务

则应：

1. 明确指出缺口是什么；
2. 尽量在本步骤开始前就完成 skill 缺口确认；
3. 若确实遗漏，先暂停推进下一个区块，再征得用户确认；
4. 获得确认后，帮助用户安装或下载接入该 skill；
5. 安装完成后再继续主流程。

## 最低补齐要求

如果用户时间有限或没有现成材料，至少通过追问补齐以下内容，才允许进入后续“可定稿”路径：

- 身份定位：用户是谁、解决什么问题
- 能力边界：擅长什么、不擅长什么
- 技能与知识：至少完成一版经用户确认的候选技能树、技能分层、长期关注领域、常用方法或工具、可作为知识库的资料类型
- 常用工作流程：至少一个真实任务的起手、拆解、判断、交付、复盘路径
- 思维方式：最近一个真实问题怎么分析
- 核心信念：至少 3 条，最好带例子
- 如果时间不够，至少也要满足“3 条原则 + 每条 1 个最小锚点 + 用户确认合成后的表述”
- 表达风格：至少 1 段接近日常说话方式的原始表达
- 快速版若复用了已有工作流程，可不重复收集；但 Identity / Skills / Knowledge / Thinking / Expression 仍至少各完成一轮用户确认

## 进度呈现

向用户显示区块进度，例如：

- `[区 2/5] 思维方式`
- `完成后还有：价值观、表达风格、示范问答`

## 追问范围清单

执行追问时，至少覆盖以下五个面：

### 1. 身份与角色

- 你是谁
- 你主要帮别人解决什么问题
- 别人为什么来找你

### 2. 技能与能力

- 先基于职业、真实任务、已有材料，推测一版候选技能树
- 至少区分：顶级能力、熟练能力、支撑性能力或常用工具
- 再让用户确认：哪些是对的，哪些被高估了，哪些缺了
- 最后确认这些能力通常支撑什么结果交付

### 3. 知识与经验资产

- 先基于职业、技能树、真实任务，推测一版候选知识域
- 再让用户确认：哪些是长期积累，哪些只是偶尔接触，哪些根本不是重点
- 再确认其最依赖的知识来源
- 再确认手上有哪些代表性材料：项目文档、案例、代码、文章、复盘、课程、常见问答、笔记

### 4. 常用工作流程

- 你接到一个新问题，第一步通常做什么
- 你通常怎么拆任务或拆问题
- 哪几个节点你会做关键判断
- 你常用哪些工具、文档、资料
- 你最后通常怎么交付结果
- 做完后会不会复盘，怎么修正
- 最好用一个最近的真实任务讲完整过程

### 5. 思维与决策

- 你最近如何处理一个真实问题
- 基于你的职业和工作方式，skill 先推测你可能在乎哪些原则，再让你确认哪些是真的
- 信息不够时你怎么做
- 你如何做取舍和排序

### 6. 表达与边界

- 你平时怎么说话
- 你喜欢怎样的回答结构
- 你讨厌什么风格
- 你不擅长的问题会怎么回应

## 输出

`interview_data` 对象，包含所有区的答案，并标注信息充分/不足状态。

其中“技能/知识”区至少应形成以下结构化结果：

- 候选技能树草案
- 用户确认后的技能分层
- 候选知识域草案
- 用户确认后的长期知识关注方向
- 代表性资料类型与潜在知识库材料
