# Step 01: 职业与技能解析

> 用户可见步骤：Step 1｜建立轮廓

## 输入

- 用户描述的职业
- 用户描述的核心技能（可选，若未明确提供则从工作内容中推测）
- 用户描述的工作内容或最近一个真实任务
- 用户长期关注或积累的知识领域（可选，若未明确提供则后续推测）
- 用户已有的可上传资料类型（可选）
- 用户平时最典型的一类工作流程（可选）

## 处理逻辑

1. 提取职业关键词。
2. 调用 `prompts/profession_analyzer.md` 生成能力配置。
3. 基于职业、真实工作内容、已有材料线索，先推测一版候选技能树和候选知识域，不要求用户从零自己列清单。
4. 向用户展示该候选树，只要求其确认、修正、删减、补充，不把“自己先整理技能/知识清单”作为前置任务。
5. 在后台判断是否已有材料可先分析，这不是一个单独的用户选择步骤。
6. 如果用户已有大量本人资料但尚未整理，可在本步骤内调用辅助 skill 处理资料，不切换主流程。
7. 如果需要联网补充行业或职业信息，默认走 `references/multi-search-engine/SKILL.md`。
8. 如果此时已经发现后续流程会依赖某个缺失 skill，应在进入深度访谈前先征得用户确认并帮助安装。
9. 在本步骤末尾，只向用户提出一个可见选择：今天走快速版还是完整版。

前置条件：

- 已完成 `steps/00_skill_check.md`
- 已知道当前环境中哪些辅助 skill 可用

## 可调用的辅助 skill

- `content-harvester`：整理用户已有内容
- `docx` / `pdf` / `xlsx`：从文件里提取技能、知识、案例线索

注意：

- 这里只能调用当前环境已确认可用的 skill
- 所有联网搜索默认先走内置的 `multi-search-engine` 本地副本

## 引导话术

向用户说：

“我们先了解一下你的职业背景。
请告诉我：
1. 你的职业是什么？
2. 你最近最能代表自己的一类真实工作是什么？
3. 如果你脑子里已经有几个最核心的能力，也可以顺手说，但不用先整理成清单。
4. 你有没有现成材料可以上传？代码、文档、方案、文章都算，没有也可以直接开始。

不需要很正式，用你平时介绍自己的方式说就好。” 

## 输出

`skill_config` 对象，包含：

- `universal_skills`: 通用技能列表
- `professional_skills`: 专业技能列表
- `knowledge_base_recommendations`: 建议上传的资料列表

同时确认以下基础信息是否已有：

- 候选技能树是否合理，例如“顶级技能 / 熟练技能 / 支撑技能”的分层
- 长期关注的候选知识领域是否合理
- 已有资料类型，例如文档、代码、案例、文章、复盘
- 最典型的工作流程轮廓，例如“先调研 -> 再拆解 -> 再验证 -> 再交付”

## 异常处理

- 职业描述过于模糊，例如“做互联网的”时，追问具体角色。
- 技能列表为空时，不要求用户强行列项；先让用户描述日常工作内容，再由 skill 提取候选技能树让其确认。
- 如果知识领域和资料类型完全为空，至少追问“你最近长期在解决哪类问题”和“你手上有哪些能代表你经验的材料”，再由 skill 推测候选知识域。

## 衔接

输出确认后，告知用户：

“好的，我了解了。

如果你有现成材料，我会先分析材料，再补充几个关键问题。
如果你没有材料，我们就直接做访谈。

接下来关于技能和知识，不需要你先自己列完整清单。
我会先根据你的职业和真实工作内容，给出一版候选技能树和知识域，再让你确认哪里对、哪里不对。

如果你的典型工作流程需要额外能力支持，我会先告诉你需要补什么 skill，再继续。

你今天想做完整版（1-2 小时，还原度 70-80%），还是快速版（30 分钟，还原度 60%）？”
